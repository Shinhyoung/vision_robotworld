## 1. 개요

컨베이어 정지 스테이션에서 MC 나일론 블록 3종을 검사하고, 양품에 한해 6D 포즈를
계산하여 **ROS 2 토픽으로 로봇 부서에 전달**하는 시스템이다.

```
트리거 → 캡처 → 표면 불량 검사 ─┬─ NG → 결과만 발행 (포즈 계산 생략)
                                └─ OK → 6D 포즈 계산 → 결과 발행
                                                          ↓
                                        /roboworld/part_result  ← 로봇 부서 계약
```

### 범위

| 구분 | 내용 |
|---|---|
| ✅ **본 프로젝트** | 카메라 입력 · 불량 검사 · 6D 포즈 · ROS 2 발행 |
| ❌ 로봇 부서 | 로봇 제어 · 모션 플래닝 · grasp · pick & place |

**최종 산출물의 핵심은 로봇 부서와의 인터페이스 규격(ICD)** 이다. 트리거 1회당
메시지 정확히 1건을 발행하며, 검사 실패·포즈 실패·하드웨어 오류에도 반드시 1건이
나간다.

### 대상 부품

| 부품 | 치수 | CAD |
|---|---|---|
| Guide Block | 200 × 55 × 55 mm | `01_input/01_Guide_Block.ply` |
| Spacer Block | 200 × 55 × 55 mm | `01_input/03_Spacer_Block.ply` |
| End Stopper | 200 × 55 × 55 mm | `01_input/05_End_Stopper.ply` |

## 2. 사용 모델 및 기술 스택

### 2.1 고정 스택 (claude.md §1)

| 구분 | 선택 |
|---|---|
| OS / 미들웨어 | Ubuntu 22.04 (WSL2) + ROS 2 Humble |
| 언어 | Python 3.10 |
| GPU | RTX 5070 (Blackwell sm_120), CUDA 12.x |
| 카메라 | Intel RealSense D455 (RGB-D) |
| 빌드 | colcon |

### 2.2 알고리즘 — 이중 백엔드 구조

각 기능에 **운영 목표 모델**과 **CPU 참조 구현**을 함께 두었다.

| 기능 | 운영 목표 | CPU 참조 구현 | 스텁 |
|---|---|---|---|
| 불량 검사 | **EfficientAD** (anomalib) | `statistical` | `stub` |
| 6D 포즈 | **FoundationPose** (Isaac ROS) | `icp` | `stub` |

**이 구조를 택한 이유**: GPU·Isaac ROS·카메라가 준비되기 전에도 전체 파이프라인이
실제로 동작해야 병렬 개발과 CI 검증이 가능하다. 현재 CPU 참조 구현만으로
검사·포즈가 모두 동작하며, 아래 §4의 측정치는 전부 이 백엔드 기준이다.

#### 검사 — `statistical` (위치 비의존 PaDiM 변형)

부품이 임의의 방향으로 도착하므로 위치별 통계가 아닌 **전역 가우시안 1개**를 사용한다.

1. 격자 패치(16 px, stride 8) 분할
2. 패치당 7차원 특징 (RGB 평균, 명암 표준편차, 그래디언트 평균/최대, 국소 대비)
3. 정상 부품 표면 패치에 다변량 가우시안 적합
4. 마할라노비스 거리 → 이상 점수

**조명 정규화**가 핵심이다. 특징 추출 전 부품 영역의 median 밝기를 고정값으로 맞춘다.
없으면 주변광 변화·노출 자동조정·부품이 화면 가장자리로 이동하는 것까지 전부
"불량"으로 읽힌다.

#### 포즈 — `icp` (CAD 정합)

1. RANSAC 평면 추정 → 평면 위 높이 밴드 → 연결 성분 분리
2. **이산 8가지 놓임 가설** (블록이 놓일 수 있는 4개 면 × 장축 방향 2가지)
3. scene→model 방향 point-to-point ICP
4. 2단계 탐색 — 저해상도로 전 가설 평가 후 승자만 정밀화

임의 yaw 스윕이 아니라 이산 가설을 쓴다. 200 mm 블록은 세워지지 않으므로 실제로
가능한 자세만 시도하는 것이 빠르고 정확하다.

### 2.3 라이선스 주의 ⚠️

**FoundationPose 공개판은 비상업(NC) 라이선스**이다. 데모·평가 목적에 한해 사용
가능하며, 상용화 시 NGC 상업판 전환이 필요하다.

## 3. 개발 내용

### 3.1 핵심 설계 결정 — ROS 비의존 코어

```
roboworld_core/          ← 모든 로직. rclpy import 없음
   ↑
roboworld_ros_utils/     ← 메시지 ↔ numpy 변환, QoS (유일한 ROS 경계)
   ↑
inspection / pose / pipeline 노드   ← 얇은 어댑터
```

그 결과 **ROS·CUDA·카메라가 없는 환경에서 182개 유닛 테스트와 E2E dry-run이 모두
통과**한다. 동일한 상태 기계가 in-process(테스트)와 3-프로세스(운영)에서 한 벌만
존재하므로 두 경로가 어긋날 수 없다.

### 3.2 패키지 구성 (7개)

| 패키지 | 역할 |
|---|---|
| `roboworld_interfaces` | **로봇 부서 계약** — msg 3, srv 3, action 1 |
| `roboworld_core` | 설정 · 기하 · 목업 · 검사/포즈 백엔드 · 인덱스 사이클 상태기계 |
| `roboworld_ros_utils` | 메시지 변환 · QoS · 파라미터 브리지 |
| `roboworld_inspection` | 검사 노드 (`InspectPart` 서비스) |
| `roboworld_pose` | 포즈 노드 (`EstimatePose` 서비스, TF 변환) |
| `roboworld_pipeline` | 오케스트레이션 · 프레임 소스 · 목업 카메라 · 트리거 |
| `roboworld_bringup` | launch · config(단일 진실 원천) · CAD 배포 |

### 3.3 규모

| 항목 | 분량 |
|---|---|
| 코어 · 노드 | 6,844 줄 |
| 테스트 | 2,045 줄 (182개) |
| 개발 도구 | 2,735 줄 (10종) |
| 문서 | 2,054 줄 |

### 3.4 개발 도구

| 도구 | 용도 |
|---|---|
| `e2e_dryrun.py` | **계약 검증 게이트** — 전체 사이클 실행 후 모든 발행 메시지를 ICD에 대조 |
| `evaluate.py` | 검출률 · 포즈 정확도 측정 (허용치 게이트) |
| `live_view.py` | 실시간 RGB-D 뷰어 (목업 / 실 카메라 / MJPEG) |
| `visualize.py` | 결과 영상 패널 저장 (컬러·깊이·분할·이상맵) |
| `reconstruct_part.py` | **D455 depth로 부품 메시 복원** (CAD 불필요) |
| `capture_part.py` | 신규 부품 촬영 (검사 학습용) |
| `register_part.py` | 촬영본으로 검사 모델 학습 + 부품 등록 |
| `check_symmetry.py` | 부품 대칭 모호성 정량화 |
| `generate_mock_dataset.py` / `export_mock_images.py` | 목업 데이터셋 생성 · PNG 변환 |

### 3.5 검증 체계

| 계층 | 도구 | 검증 대상 |
|---|---|---|
| 유닛 | pytest (182개) | 기하 · 설정 · 백엔드 · 상태기계 |
| **계약** | `test_contract.py` + `e2e_dryrun.py` | `.msg` ↔ 코드 정합, 발행값 규칙 |
| 정확도 | `evaluate.py` | 검출률 · 포즈 오차 (허용치) |
| 통합 | `colcon test` | ROS 빌드 · 린트 |

**계약 검증과 정확도 검증을 분리**했다. dry-run은 인터페이스를 지키는 게이트이며,
소수 사이클로 검출 정확도를 판정하지 않는다. 섞으면 CI가 인터페이스와 무관한 이유로
깨진다.

## 4. 측정 결과

> 모의 데이터(CAD 렌더링) + CPU 백엔드 기준. 실 카메라·EfficientAD·FoundationPose
> 전환 후 재측정이 필요하다. 재현: `make evaluate`

### 4.1 검사 (부품별 양품 25 / 불량 25)

| 부품 | 미검출 | 과검출 | margin | 추론 |
|---|---|---|---|---|
| guide_block | **0 / 25** | 1 / 25 | +0.047 | 62 ms |
| spacer_block | **0 / 25** | 1 / 25 | −0.162 | 62 ms |
| end_stopper | **0 / 25** | 1 / 25 | +0.002 | 62 ms |

**미검출 0건**(불량 유출 없음). 단 **margin(양품 최고점 − 불량 최저점)이 좁다.**
end_stopper의 얕은 스크래치는 임계값 0.500에 대해 0.492↔0.526으로 진동하며,
학습량을 늘려도 해소되지 않는다 — 특징 민감도의 한계다. EfficientAD 전환 후
재측정이 필요하다.

### 4.2 포즈 (작업 거리 0.6 m, 대칭 보정 후)

| 부품 | 위치오차 중앙/최대 | 자세오차 중앙/최대 | 추론 |
|---|---|---|---|
| guide_block | 1.36 / 3.69 mm | 0.72 / 1.78° | 104 ms |
| spacer_block | 0.95 / 2.52 mm | 0.58 / 2.29° | 102 ms |
| end_stopper | 0.93 / 2.40 mm | 0.52 / 1.83° | 112 ms |

### 4.3 작업 거리 특성

| 거리 | 위치오차 중앙/최대 | 판정 |
|---|---|---|
| 0.6 m | 0.6 / 1.9 mm | ✅ **설계값** |
| 0.8 m | 1.3 / 2.8 mm | ✅ |
| 1.0 m | 1.9 / 2.5 mm | ⚠️ |
| 1.25 m | 6.1 / 9.8 mm | ❌ |

depth 노이즈가 거리 제곱에 비례하므로 **0.8 m 이내를 권장**한다.

### 4.4 택트 타임

| 구간 | 예산 | 실측 |
|---|---|---|
| 검사 | 400 ms | 62 ms |
| 포즈 | 900 ms | ~110 ms |
| **전체** | 1200 ms | **258 ms (중앙값)** |

NG 사이클은 포즈를 생략하므로 165~197 ms로 더 짧다.

## 5. 추가 구현 — CAD 없는 신규 부품 등록

CAD가 없는 부품도 촬영만으로 등록할 수 있다.

| 기능 | CAD 없이 | 근거 |
|---|---|---|
| 불량 검사 | ✅ 동작 | 검사기는 형상을 참조하지 않음 |
| 부품 분할 | ✅ 동작 | depth 평면 제거 방식 |
| 6D 포즈 | ✅ **메시 복원 후 동작** | D455 depth로 복원 |

**복원 방식**: 부품이 평면 위에 놓인다는 점을 이용해 높이맵을 만들고 아래로 압출한다.
depth는 무늬가 필요 없어 무텍스처 부품에 오히려 유리하고, 실척이 그대로 나온다.

**실측 검증** (200×55×55 mm 블록):

| 항목 | 결과 |
|---|---|
| 복원 치수 오차 | +2.0 / +1.0 / +1.1 mm |
| 복원 메시로 포즈 추정 | 위치오차 1.1 ~ 1.9 mm |
| 동일 조건 **실제 CAD** | 1.6 mm |

**복원 메시가 CAD와 동등한 포즈 정확도**를 보였다. 성능을 결정하는 것은 모델 정확도가
아니라 관측 depth의 품질이기 때문이다.

> 제약: 바닥면이 평평한 각기둥형 부품에 정확하다. 언더컷은 복원되지 않는다.
> 등록 거리와 작업 거리를 맞춰야 한다.

## 7. 로봇 부서 회신 필요 사항

### ⚠️ 7.1 자세 대칭 모호성 — 최우선

세 부품 모두 55×55 정사각 단면이라, 단일 시점 depth로는 자세가 **order-8 대칭군까지만**
결정된다. 위치는 영향 없다.

| 부품 | 실측 뒤집힘 빈도 | 형상 구분 |
|---|---|---|
| guide_block | 84 % | 불가 |
| spacer_block | 68 % | 불가 |
| end_stopper | 12 % | 가능 |

**질문: 파지(grasp)가 이 대칭에 불변인가?**

- 장축 중앙을 위에서 잡는 방식 → **불변. 문제 없음**
- 특정 피처를 기준으로 잡는 방식 → **최대 120 mm 오차**. guide_block과
  spacer_block은 알고리즘으로 해결 불가이며 설계 변경(비대칭 마커) 또는
  카메라 추가가 필요하다

### 7.2 기타 미결

| 항목 | 내용 |
|---|---|
| 좌표계 | `world` 프레임 정의, hand-eye 캘리브레이션 책임 주체 |
| 시스템 구성 | PC 1대 / 2대 선택 → **전달물이 달라짐** (ICD §10) |
| 설치 거리 | 권장 0.6 m, 상한 0.8 m |
| 목표치 | 요구 택트 타임 · 정확도 (현재 예산은 비전팀 가정값) |

## 8. 결론

인터페이스 계약과 전체 파이프라인이 완성되어 **하드웨어·GPU 없이도 실제로 동작하고
CI가 이를 검증**한다. 로봇 부서는 목업 모드로 즉시 연동 개발을 시작할 수 있다.

기술적으로 가장 중요한 발견은 **부품 대칭 모호성**이다. 이는 알고리즘 성능 문제가
아니라 형상에서 오는 원리적 제약이며, 대응 방향이 파지 방식에 따라 달라진다.
**설계 변경이 필요할 수도 있으므로 가장 먼저 확인해야 한다.**
